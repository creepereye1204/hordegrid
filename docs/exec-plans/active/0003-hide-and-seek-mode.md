# 0003: 숨바꼭질 모드
Status: Active · Owner: claude · Started: 2026-09-18

## 목표
같은 hordegrid 앱 안에 타이틀 화면 "게임 종류 선택"을 추가하고, 그 중 하나로 시야 기반 숨바꼭질 모드(술래 1명 이상이 나머지를 시야로 찾아내는 방식)를 만든다.

## 범위 / 비범위
**범위**
- 타이틀 화면에 모드 선택 UI (생존 / 숨바꼭질)
- 숨바꼭질 규칙: 라운드 시작 시 역할 배정(술래 N / 숨는 사람 M), 술래의 시야(시야각+거리, 장애물에 가려짐)에 일정 시간 노출되면 "발견", 전원 발견되거나 타이머 종료 시 라운드 종료
- 시야/가시성 계산: 맵 타일 기반 레이캐스트 (기존 `crates/sim/src/grid.rs` 타일맵 재사용)
- 기존 WebRTC 매칭·GGRS 롤백·Pages 배포 인프라 재사용 — 새 서버/시그널링 없음 ([core-beliefs.md](../design-docs/core-beliefs.md) 원칙 1 적용)
- 최소 1개 맵, 터치 조작 지원 (mobile-play AC 준수)

**비범위 (이번 계획에서 제외)**
- 캐릭터 커스텀 GIF 업로드 — 사용자가 자기 GIF를 아바타로 쓰는 기능은 **나중에 별도 계획**으로. 이번엔 기존 픽셀 아바타/색상 블록으로 대체
- 오리지널 고양이 캐릭터 아트 제작 — 위와 같은 이유로 보류
- 봇/싱글플레이 숨바꼭질 (지금은 멀티플레이만)

## 단계
- [ ] 1. 설계 문서 `docs/design-docs/hide-and-seek-mode.md` 작성: 역할 배정 알고리즘, 시야각/거리 상수, "발견" 판정(연속 프레임 수), 라운드 타이머, 승리 조건, `sim::State`에 추가할 POD 필드 (검증: 리뷰 후 core-beliefs 위반 없음 — 특히 결정론·POD 규칙)
- [ ] 2. `crates/sim`에 모드 enum + 숨바꼭질 스텝 함수 추가 (기존 웨이브/좀비 로직과 분리, `grid.rs` 레이캐스트 재사용) (검증: `just sim-test` 신규 유닛 테스트)
- [ ] 3. `crates/web` (`Game` API)에 모드 선택 파라미터 노출 (검증: `just check`의 tsc가 `web/types/hg_web.d.ts` drift 잡아줌)
- [ ] 4. 타이틀 화면에 모드 선택 UI 추가 (`web/index.html`, `web/src/main.ts`) — 로비 흐름은 기존 재사용 (검증: 수동 플레이, `web/scripts/lint-arch.mjs`)
- [ ] 5. 렌더링: 술래/숨는 사람 시점에 따라 다르게 보여줄 정보 결정 (전체 상태는 GGRS로 모든 피어에 동기화되므로, "안 보임"은 **클라이언트 렌더 필터**로 구현 — sim 자체는 항상 전체 상태 보유) (검증: 수동 플레이 — 술래 화면에서 숨은 사람이 실제로 안 그려지는지)
- [ ] 6. `just netsim` 통과 확인 (입력 인코딩 바뀌면 필수, [AGENTS.md](../../AGENTS.md) 규칙)
- [ ] 7. 2대 폰 실기 테스트: 방 생성 → 모드 선택(숨바꼭질) → 역할 배정 → 라운드 진행 → 승리 조건 확인

## 리스크 & 확인할 가정
- **정보 은닉 vs 롤백 동기화 충돌**: GGRS 롤백은 결정론적 전체 상태 동기화가 전제라, "술래가 숨은 사람 위치를 sim 레벨에서 모른다"를 만들 수 없다 (모든 피어가 전체 상태를 가짐). 은닉은 반드시 클라이언트 렌더 계층에서만 처리해야 함 — 이 가정이 틀리면 설계 자체를 다시 봐야 한다
- 4인 이하 소규모라 역할 배정 불균형(술래 1명 대 다수) 밸런스는 플레이테스트로 조정 필요, 수치는 별도 확인 없이 우선 확정하지 않는다
- 시야 레이캐스트가 프레임당 비용을 얼마나 먹는지 `bench` 예제로 측정 필요 ([core-beliefs.md](../design-docs/core-beliefs.md) 원칙 6)

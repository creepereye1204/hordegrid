# PRODUCT SENSE

기능 추가/변경을 판단하는 기준. 에이전트가 "이거 넣을까?"를 스스로 판단할 때 쓴다.

## 이 게임은 무엇인가
**"링크 하나 보내면 친구랑 바로 좀비 떼를 쓸어버리는 10분짜리 협동 게임."**
포트폴리오로서는 **"서버 0대로 롤백 넷코드 멀티플레이를 실제로 돌린다"** 를 증명하는 물건.

## 우선순위 (충돌 시 위가 이긴다)
1. **같이 들어가기 쉬움** — 로그인·설치·설명 없음. 마찰을 늘리는 기능은 거의 항상 기각
2. **손맛/반응성** — 입력 지연·끊김 체감 없음. 롤백 튐이 거슬리면 콘텐츠보다 먼저 수정
3. **결정론 유지 가능성** — 멋진 기능이라도 sim을 비결정적으로 만들 위험이 크면 표현 계층으로만
4. **콘텐츠 양** — 무기·적·맵은 마지막

## 판단 질문
- 이 기능이 **서버를 요구**하나? → 기각 (core-beliefs #1)
- **첫 판 시작까지 클릭 수**를 늘리나? → 기본값 끄기 or 기각
- sim 상태 크기를 크게 늘리나(>4KiB)? → performance 예산 확인 후
- **폰에서도 되나?** 터치로 못 쓰는 기능은 PC 전용으로 넣지 말고 설계를 다시
- 포폴 리뷰어가 **30초 데모에서 알아볼 수 있나**? → 알아볼 수 없으면 Phase 4 이후

## 명시적 비목표
PvP 랭크, 계정/진행도 저장, 공개 매칭, 채팅, 과금, 네이티브 앱 스토어 패키징(모바일 **브라우저**는 1급 지원), 5인 이상

## 용어
| 용어 | 뜻 | 코드 이름 |
|---|---|---|
| 방 / 초대코드 | 숫자 8자리 코드로 식별되는 로비 | `InviteCode` |
| 방장 | 방을 만든 피어, 입장 승인 권한 | `host` |
| 피어 | WebRTC로 연결된 다른 브라우저 | `PeerId`(trystero), `PeerSlot`(GGRS 주소) |
| 플레이어 핸들 | 게임 내 플레이어 번호 0..n | `PlayerHandle` |
| 프레임 | sim 1스텝 (1/60초) | `Frame` |
| 확정 프레임 | 모든 피어 입력이 도착한 프레임 | confirmed frame |
| 떼 | 동시에 몰려오는 적 무리 | `horde` |
| 설치물 | 바리케이드·폭발통 | `Placeable` |
| 다운 | HP 0, 부활 대기 | `Downed` |
| present | 입력 bit15, 연결 중인 플레이어 | `present` |
